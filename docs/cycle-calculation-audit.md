# Аудит расчёта циклов LunaPair

Дата аудита: 2026-07-14.

## Найденная причина расхождений

В прежней реализации расчёт прогноза и фактические циклы были недостаточно разделены:

- старый календарь открывал действие создания цикла прямо по клику на дату;
- `startPeriod(date)` всегда добавлял новый `CycleEntry`, без проверки соседних дат и без сценария «это продолжение текущих месячных»;
- история и статистика брали `cycleLength` из всех записей `CycleEntry`, включая подозрительные интервалы;
- календарь рассчитывал прогноз относительно даты просматриваемого месяца/ячейки, а главная страница — относительно текущей даты;
- текущий незавершённый цикл мог выглядеть как завершённый короткий цикл, если рядом появлялись ошибочные старты.

Из-за этого могли появляться циклы за 29 и 30 июля продолжительностью 1 день, а разные экраны показывали разные даты прогноза.

## Почему возникали циклы по 1 дню

Причина не в медицинском алгоритме, а в модели действий:

1. Дата кровотечения могла быть сохранена как новое начало месячных.
2. Следующая соседняя дата также могла быть сохранена как новое начало.
3. При пересчёте `cycleLength` интервал между соседними стартами становился 1 день.
4. Такие интервалы попадали в среднее значение и искажали статистику.

## Почему календарь и главная страница показывали разные прогнозы

Главная страница использовала прогноз от текущей даты, а календарь вычислял состояние каждой даты через тот же метод, но с датой ячейки. Для будущего месяца это фактически могло сдвигать базовую точку расчёта и показывать другой прогноз.

## Изменённые файлы

- `src/features/cycle/domain/cyclePredictionService.ts` — единый сервис прогноза.
- `src/features/cycle/domain/dateUtils.ts` — безопасные операции с локальными календарными датами.
- `src/features/cycle/domain/cycleCalculations.ts` — старый API теперь делегирует расчёт единому сервису.
- `src/stores/appStore.ts` — добавлена защита от дублей стартов.
- `src/features/cycle/pages/CalendarPage.tsx` — календарь больше не создаёт циклы при просмотре или простом клике.
- `src/features/assistant/pages/AssistantPage.tsx` — объяснение прогноза берётся из единого результата.

## Совместимость со старыми данными

Старые записи не удаляются автоматически. Подозрительные интервалы 0–14 дней исключаются из прогноза, но остаются в истории пользователя для проверки. Миграция IndexedDB v2 идемпотентна и добавляет отсутствующие поля без очистки таблиц.
